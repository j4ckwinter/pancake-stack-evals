# Three-arm comparison, 9 October 2026

The scoped pilot found additional workflow overhead without a gain on the predeclared artifact probes. All twelve saved artifacts pass the corrected probes. Eleven runs completed within the five-minute limit. Poteto timed out on one migration and its other migration narrowed the public numeric contract. These observations do not establish general superiority.

## Method

Two fresh repetitions of an exact-byte CLI typo correction and a versioned invoice migration ran under baseline Codex, source Pancake, and the installed Codex adaptation of Poteto. All parent and worker records report `gpt-6.1-sol` with medium effort on Codex CLI 0.160.0. The baseline used a clean CLI profile, not the configured daily IDE environment.

All arms shared the same public requests, temporary profiles, scope, delegation permission, and five-minute candidate limit. Order rotated. Two repetitions do not fully balance positions within each task. Candidates saw their own guidance but not assessor probes or other treatments. A separate reviewer received neutral output labels; prose and worker topology prevented complete blinding.

Pancake source was `f2b1a4024a67367d1e4a9ed6162ccfbc9ae23fbb`. Trials used evaluator `c2b044ea3eb460519942f58af4926d6fda04bfe2`. Corrected assessment used `e3a04e80210c87315c1d30cec324b352f3a4f11a`. The [evidence record](evidence/three-arm-comparison-2026-10-09.json) retains exact Poteto inputs, per-run outcomes, observed settings, usage, and sanitized final replies. Raw sessions remain private at `/tmp/pancake-three-arm-20261009`. Copied authentication was removed.

## Assessment corrections and additional findings

The original file gate allowed only new regression-test files. Every migration added a relevant shared validation module, so every original migration artifact verdict was a false rejection. The correction permits scoped Python and Markdown additions and behavior-preserving facade/documentation changes while preserving archives and unrelated files. A regression exercises a nested shared module and protected-file rejection. Original results remain in the evidence; no candidate was rerun.

After run 10 timed out, the standard runner stopped. The coordinator resumed only the two remaining entries through the same runner function, with the original inputs and settings. The timeout remains an incomplete run even though its saved code passes artifact checks.

Independent source review found that run 05, the completed Poteto migration, restricts values to `int` and `float` instances. The public contract says nonnegative numbers, and the original APIs accept Decimal and Fraction. A separate post-hoc audit exercised both types through creation, the billing facade, live reads, and both archive versions on all six migration artifacts. Run 05 rejected both types on every path. The other five artifacts passed. All six rejected NaN reads. These checks supplement, rather than replace, the predeclared outcomes.

Candidate tests retained the original passing coverage and added useful checks. Some invalid-version tests paired the wrong version with a mismatched field, so they could reject an input for the wrong reason. The evaluator holds independent probes, and the output review records this test-quality limit separately from production behavior.

## Decision

Keep proportional handling and measure changes before adding process. This sample supports direct handling of tiny tasks and shows that independent review alone does not establish correctness. It does not justify broad claims about either workflow. The migration is synthetic, the sample is small, and there is no clean-review false-positive comparison, installed-host comparison, Claude coverage, or provider diversity.

Reproduce preparation and execution with the [three-arm procedure](behavioral-evaluation.md#three-arm-outcome-and-proportionality-pilot). Artifact checks and evaluator tests remain distinct from live workflow evidence.
